Scripterとは

自分の力で、やり方を作れる人のこと。

ボタンは、中身を隠す

ボタンをポチッと押すだけだと、中で何が起きたか分からない。

アプリは便利。でも、中でどう動いたかは見せてくれない。うまくいかなかったとき、 なぜダメだったか自分では分からない。魔法みたいに見えるけど、魔法じゃない。

人は、自分で解いたときに伸びる

誰かにやってもらったことは、自分の力にならない。

難しい場面に出会う。仕組みを見つける。自分でやり方を組み立てる。 そこで初めて、力がつく。

Scripterの考え方

問題 → 構造 → 解法 → 実行 → 結果 → 修正

難しいこと(問題)を見つけたら → 仕組みを調べて(構造) → やり方を考えて(解法) → 実際にやってみて(実行) → どうなったか見て(結果) → ダメなら直す(修正)。これをぐるぐる回すのがScripter。

コンピュータの中身

コンピュータの中は、全部「ファイル」でできている。

  • ファイル = 1つの情報のかたまり(文章、写真、プログラムぜんぶ)
  • ディレクトリ(フォルダ) = ファイルを入れておく箱
  • パス = その箱がどこにあるか、を書いた道じるべ

ファイルシステム

/
├── home
│   └── user
│       └── a.txt

どんなファイルも、この木のような形の中の、どこかにある。迷子にはならない。

ぜんぶ「文字」でできている

Everything is text.

  • 命令(コマンド)も文字
  • 設定も文字
  • 記録も文字

なぜ文字がいいのか

  • あとから直せる
  • そのまま保存できる
  • 前と今を見くらべられる
  • いつ何をやったか、記録が残る
  • コンピュータに自動でやらせられる

コマンドとは

コンピュータへの、短い命令文。

コマンド + 引数 + 対象

例: 「掃除して(コマンド) → ていねいに(引数) → 部屋を(対象)」と同じ形。

最初に覚える8個

pwd今どこにいるか見る
ls中身を見る
cd移動する
mkdirフォルダを作る
touch空のファイルを作る
mv動かす・名前を変える
cpコピーする
rm消す

やる場所

操作は「ターミナル」という画面でやる。

Mac、Windows(WSL)、Linux ── 見た目は違っても、中の考え方はぜんぶ同じ。

ターミナルを開こう。

クエスト 1

フォルダを作って、入る

やること

mkdir scripter
cd scripter
touch a.txt
ls

結果に a.txt が出てきたら成功。✓ クリア

mkdirで箱を作り、cdでその箱に入り、touchで空のファイルを1個置いた。 lsで「今この箱に何があるか」を確認した。

クエスト 2

ファイルに文字を書いて、読む

やること

echo "こんにちは" > memo.txt
cat memo.txt

画面に「こんにちは」が出てきたら成功。✓ クリア

echoは文字を出す命令。「>」はその文字をファイルにしまう記号。 catはファイルの中身をそのまま見せる命令。

クエスト 3

コピーして、名前を変えて、消す

やること

cp memo.txt memo_copy.txt
mv memo_copy.txt memo_old.txt
rm memo_old.txt
ls

memo_old.txt が消えて、memo.txt だけ残っていたら成功。 ✓ クリア

cpは複製、mvは移動(名前を変えるのも実は「移動」の一種)、 rmは削除。消す命令だけは取り消せないので、ここだけは慎重に。

クエスト 4

前と今を見くらべる

やること

echo "1行目" > kiroku.txt
echo "2行目" >> kiroku.txt
cat kiroku.txt

「1行目」と「2行目」が両方出てきたら成功。✓ クリア

「>」は上書き、「>>」は付け足し。この「積み重ね」の考え方が、 あとで出てくる「記録を残す(履歴)」の入り口になる。

結果

ここまでやったこと、それが「解法」だ。

難しそうに見えた「コンピュータを使う」が、ただの積み木だったと分かったはず。

もう一度、流れを見る

問題 → 構造 → 解法 → 実行 → 結果 → 修正

さっきの4つのクエストは、ぜんぶこの流れそのものだった。
